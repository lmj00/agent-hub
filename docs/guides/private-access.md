# 나만 접속하는 관리 화면

코드를 공개해도 작업 DB·GitHub 키·AI 인증·관리 화면을 공개할 필요는 없습니다. 현재 앱은 사용자 한 명의 비밀번호 로그인을 지원합니다. 여기에 비공개 네트워크를 사용하면 인터넷에서 관리 화면 주소에 직접 접속하는 경로를 없앨 수 있습니다.

## 권장 구성

```text
내 PC·휴대전화 → Tailscale 비공개 네트워크 → HTTPS Serve → 127.0.0.1:3000
                                                      → agent-hub 로그인
```

서버와 사용하는 기기를 본인 Tailscale 네트워크에 등록하고, 서버의 agent-hub는 루프백 주소로 실행합니다. Tailscale Serve는 네트워크 안에서 서비스를 공유합니다. 공개 인터넷에 노출하는 Funnel과 용도가 다릅니다. [공식 Serve 안내](https://tailscale.com/docs/features/tailscale-serve).

다른 사람도 같은 Tailscale 네트워크에 있다면 가입만으로 본인 전용이 되지 않습니다. 접근 정책에서 본인 계정·기기만 해당 서버의 HTTPS 포트에 접근하도록 제한하고, 기존의 넓은 허용 규칙도 확인합니다. 앱 비밀번호도 별도로 유지합니다.

## 적용 순서

1. 서버와 개인 기기에 Tailscale을 설치·로그인합니다. 서버 주소와 접근 정책을 확인합니다.
2. Serve가 사용할 `https://서버명.네트워크명.ts.net` 주소로 새 [로그인 설정](management.md#단일-사용자-로그인-설정)을 만듭니다. 예시 주소를 그대로 사용하지 않습니다.
3. 해당 로그인 설정으로 agent-hub를 `127.0.0.1:3000`에 실행합니다.
4. 서버에서 아래 명령을 실행합니다. [공식 CLI 문서](https://tailscale.com/docs/reference/tailscale-cli/serve)에 따라 HTTPS 설정이 필요하면 안내를 완료합니다.

```sh
tailscale serve --bg http://127.0.0.1:3000
tailscale serve status
```

기존 서비스를 공유 중인 서버라면 Serve 상태부터 확인하고, 사용할 포트·서비스를 구분해 적용합니다. 기존 트레이딩 서비스의 프록시나 방화벽을 이 설정 때문에 함께 변경하지 않습니다.

## 완료 확인

설정 파일을 작성한 것과 본인만 접근하는 것은 다릅니다. 다음을 실제 기기에서 확인해야 운영 적용이 완료됩니다.

- 허용한 기기에서 HTTPS 로그인·프로젝트 조회·변경 요청이 동작한다.
- 로그아웃한 브라우저에서는 프로젝트 API가 401을 반환한다.
- Tailscale에 연결하지 않은 기기와 정책에서 제외한 계정은 관리 화면에 접근하지 못한다.
- 서버의 공개 IP·기존 공개 프록시를 통해 agent-hub에 접근할 별도 경로가 없다.
- 서버 재시작 뒤 Serve와 agent-hub가 재개되고 로그인 보호가 유지된다.

접속 주소와 서버의 `origin`이 다르면 요청을 거부합니다. 프록시를 경유한 실제 로그인·변경 요청까지 확인하며, 문제 해결을 위해 Host·Origin·CSRF 검사를 끄지 않습니다. 이 저장소의 자동 테스트만으로 개인 네트워크 정책과 실제 기기 접근 검증까지 완료됐다고 보지 않습니다.

## 다른 방법

단기간에는 SSH 포트 전달로 서버의 루프백 포트에 접속할 수 있습니다. 이 경우 로그인 설정도 브라우저에서 사용할 정확한 로컬 주소와 맞아야 합니다. 공개 HTTPS에 앱 로그인만 두는 방법도 있지만, 관리 화면이 인터넷에서 도달 가능한 상태로 남습니다. 개인 운영의 기본 방향은 비공개 네트워크와 앱 로그인을 함께 사용하는 것입니다.
