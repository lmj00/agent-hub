# Linux 자원 검사 결과 읽기

CI는 임시 Ubuntu 서버에서 실제 systemd 서비스와 Docker 작업을 실행하고, 각 단계의 메모리·CPU·파일 크기를 기록합니다. **AI 응답은 테스트 대역입니다.** 실제 Codex의 사용량은 [별도 측정 기록](../history/resource-measurements.md)을 참고합니다.

## 어디서 보나

GitHub Actions의 CI 실행에서 `linux-lifecycle-ubuntu-22.04` 또는 `linux-lifecycle-ubuntu-24.04` 첨부 파일을 받습니다. 보관 기간은 7일입니다. `systemd-tests.log`에는 단계별 JSON 기록과 최종 검사 결과가 있습니다. 오류가 난 실행도 만들어진 기록을 보관합니다.

검사는 서비스 시작 전 → 시작 후 대기 → 작업 중 강제 종료·복구 → 정상 중지·복구 → **짧은 작업 10회 반복** → 재시작 → 최종 중지 순서입니다. 반복 작업마다 성공·종료 확인·컨테이너 제거를 확인합니다. 전체 작업은 기존 장애 시험을 합쳐 작업 12개·실행 시도 14개입니다.

## 숫자의 뜻

| 기록 | 뜻 | 해석할 때 주의할 점 |
| --- | --- | --- |
| `host` | Linux 호스트 전체 메모리. 사용 추정치는 전체에서 사용 가능량을 뺀 값 | Docker·CI·측정 도구도 포함. agent-hub만의 사용량이 아님 |
| `service` | 서버와 그 자식 프로세스가 속한 cgroup의 메모리·누적 CPU 시간 | Docker 데몬·작업 컨테이너·별도 로그 서비스는 포함하지 않음 |
| `executions` | 이 검사가 만든 실행 컨테이너별 cgroup 사용량 | 대기 중인 컨테이너를 측정. AI 작업의 최대 사용량이 아님 |
| `state`, `database`, `wal` | 상태 폴더 전체, SQLite 본체, 임시 변경 기록 파일 크기 | 뒤의 두 항목은 `state`에 포함되므로 합산하지 않음 |
| `journals` | agent-hub 전용 로그 폴더의 파일 크기 | 내용은 읽지 않음. 다른 서비스의 로그는 제외 |

메모리는 바이트, `cpuUsageUsec`는 해당 cgroup이 생성된 뒤 누적한 CPU 시간(마이크로초)입니다. `identity`가 바뀌면 새 cgroup이므로 전후 CPU 값을 빼지 않습니다. `peakBytes`는 커널이 제공하는 해당 cgroup의 최대 메모리이며, 지원하지 않는 커널에서는 `null`입니다. 현재 값과 최대값은 차례로 읽으므로 한 순간의 원자적 측정이 아닙니다.

파일 크기의 `bytes`는 파일 내용 길이, `allocatedBytes`는 파일에 할당된 디스크 블록 크기입니다. 하드링크는 각 측정 폴더 안에서 한 번만 세고, 심볼릭 링크는 따라가지 않습니다. `exists: false`는 아직 생성되지 않았거나 이미 제거된 경로입니다. `vanishedEntries`가 있으면 측정 중 사라진 항목이 있으므로 정확한 합계로 보지 않습니다. 파일 내용은 열지 않아 SQLite의 잠금에 영향을 주지 않습니다.

## 무엇까지 확인한 것인가

각 `resource-sample`은 특정 단계의 표본입니다. 일정 간격의 연속 측정이 아니며, `durationMs`만큼 측정 자체에도 시간이 걸립니다. 최종 성공 기록과 `fixture-cleanup`뿐 아니라 **CI 전체 통과 여부**를 함께 확인합니다.

이 검사는 재시작·반복 실행 경계에서 사용량을 비교하고 남은 컨테이너나 관측된 OOM을 찾기 위한 것입니다. 10개의 작업은 코드 변경을 하지 않으므로 개발 Git의 증가량은 다루지 않습니다. 짧은 표본의 증가만으로 메모리 누수를 확정하거나, 안정적인 표본만으로 누수가 없다고 판단하지 않습니다.

**2GiB 서버의 적정 사양, 실제 AI 부하, 장기간 DB·Git·로그 증가, 원격 24시간 안정성은 이 검사로 확정하지 않습니다.** 로그 폴더는 임시 VM이 폐기될 때 함께 없어집니다. 운영용 로그 보관 정책은 [운영 절차](../04-operations.md)를 따릅니다.

검사 스크립트는 임시 GitHub 호스팅 Linux VM에서만 명시적으로 허용하여 실행합니다. 운영 서버나 개인 개발 환경에서 설치·삭제 시험을 실행하는 명령이 아닙니다. 각 상태 대기에는 30초 제한과 5분의 공통 마감 시각을 적용하며, CI 작업 전체에도 20분 제한을 둡니다.

수치 정의는 Linux의 [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)와 [/proc](https://www.kernel.org/doc/html/latest/filesystems/proc.html) 문서를 기준으로 합니다.
