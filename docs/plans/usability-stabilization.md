# 사용 흐름과 공개 경계 안정화

## 목표

첫 사용부터 자율 작업 관리까지의 흐름을 검증하고 발견한 결함을 수정합니다. 공개·비공개 경계와 기존 실행 규칙을 유지하며 검증 결과와 남은 운영 과제를 정리합니다.

공개 프로젝트 화면이 포함된 최신 코드를 기준으로 별도 작업 브랜치에서 진행합니다. 기능을 늘리거나 전체 구조를 다시 만드는 것이 목표는 아닙니다.

## 작업 단위와 완료 기준

| 작업 단위 | 확인할 결과 |
| --- | --- |
| 첫 사용 흐름 | 로그인 → 프로젝트 연결 → 목표 등록 → 진행·대기·결과 확인에서 막히는 동작과 잘못된 안내 수정 |
| 장애와 복구 | 연결 끊김·세션 만료·저장 응답 유실·서버 재시작 때 기록과 실행 제한을 보존하고 중복 실행 방지 |
| 공개 경계 | 익명 사용자의 관리 API 접근과 변경 거부, 공개 철회 반영, 비공개 정보가 목록·오류 응답에 포함되지 않음을 확인 |
| 결과 정리 | 변경별 실제 검증 결과, 주요 화면 캡처, 소유자가 직접 확인할 항목과 남은 운영 과제 기록 |

## 진행 기준

- 일반적인 구현 결정은 기존 사용자 방향·문서·코드를 기준으로 내리고 근거를 남깁니다. 사용자의 변경을 보존합니다.
- Ponytail의 최소 변경 원칙을 적용하고, 기존 구조와 의존성을 우선 사용합니다. 필요한 검증이나 보안·복구 규칙은 줄이지 않습니다.
- 기존 검사로 확인되는 항목은 그대로 재사용합니다. 발견한 결함은 재현 후 수정하고 관련 검사를 다시 실행합니다. 수정 이유 없는 리팩터링이나 구현을 그대로 따라 쓰는 테스트는 추가하지 않습니다.
- gstack의 검토·검증과 변경한 화면의 실제 브라우저 확인을 수행합니다. 의미 있는 변경 단위로 결과를 정리합니다.
- 예제·대역 검증과 실제 계정 연동 검증을 구분합니다. 실제 인증이 필요한 항목은 미확인으로 기록하며 통과로 표시하지 않습니다.
- 운영 배포·외부 공개 접근 변경·트레이딩 서비스 변경·새 외부 계정 설치는 이 안정화 작업에 포함하지 않습니다.

정한 흐름과 공개 경계를 검증하고, 확인한 결함의 수정·재검증 및 결과 정리를 마치면 종료합니다. 시간이 남는다는 이유로 새 기능을 추가하지 않습니다.

실행한 검사와 확인하지 못한 운영 항목은 [검증 기록](../history/usability-stabilization.md)에 정리합니다.
