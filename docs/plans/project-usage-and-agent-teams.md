# 프로젝트 사용량과 자율 역할 배정

목표는 프로젝트별 AI 사용량을 확인하고, 총괄이 작업에 필요한 전문 역할을 정해 실행하도록 하는 것입니다.

## 설계 결정

- **사용량:** 기존 Step 기록을 프로젝트·모델별로 합산합니다. 재시도도 포함하고 캐시 입력은 전체 입력의 일부로 계산합니다. 진행 중인 호출과 토큰이 보고되지 않은 종료 호출은 별도로 셉니다.
- **비용:** 확인된 모델에 한해 기준일의 API Standard 단가로 환산합니다. 실제 청구액·구독 잔여량이 아니며, 장문 요금·도구 사용료·서비스 등급 차이는 반영하지 않습니다. 모르는 모델은 비용 미산정으로 표시합니다.
- **조회:** 소유자용 사용량 화면과 API를 추가합니다. 공개 프로젝트여도 사용량·역할 지시는 공개 API에 포함하지 않습니다. SQL에서 합산하고 화면을 열었을 때만 갱신합니다.
- **에이전트:** 총괄이 작업마다 전문 역할의 키·이름·임무를 제안합니다. 같은 목표에서는 기존 역할을 재사용합니다. 역할과 임무를 작업의 변경 불가능한 계획 스냅샷에 저장하고 실제 개발 호출에 전달합니다. 별도 상시 프로세스나 인증 계정을 만드는 기능은 아닙니다.
- **협업:** 다음 총괄에게 기존 역할과 작업 결과를 전달합니다. 개발과 독립 검토 호출은 분리하며, 검토자는 개발 역할의 지시를 자기 권한으로 사용하지 않습니다. 서버 전체 Run 하나라는 실행 규모를 유지합니다.
- **경계:** 역할은 도구·모델·권한·재시도 제한을 결정하지 못합니다. 역할 이름을 바꿔도 작업 중복·실패 억제·종료 확인 규칙은 그대로 적용합니다. 기존 작업에는 역할을 임의로 소급 부여하지 않습니다.

별도 에이전트 등록 테이블과 생성 API 대신 기존 계획 스냅샷을 재사용합니다. 역할의 존재·담당 작업·상태는 저장된 작업에서 조회합니다. 독립적인 수명이나 동시 실행 제어가 필요해지면 별도 등록 모델을 검토합니다.

## 구현 단위와 검증 기준

1. **프로젝트 사용량 조회:** 계약·SQL 집계·소유자 API·화면. SQLite에서 프로젝트 격리, 여러 모델·재시도·캐시·미보고·실행 중 호출을 검사합니다. 인증 없는 조회를 차단하고, 실제 브라우저에서 프로젝트 이동과 오류·빈 상태를 확인합니다.
2. **자율 역할 배정:** 계획 출력 계약·입력 검증·작업 스냅샷·개발 프롬프트·총괄 이력·팀 조회 화면. 이전 계획과의 호환, 역할 재사용·무효 입력·중복 작업 억제·실제 호출에 임무 전달·독립 검토 경계를 검사합니다.
3. 각 단위에서 타입·린트·빌드·관련 테스트와 독립 코드 리뷰를 수행합니다. 실제 AI 실행과 모의 테스트 결과를 구분합니다. 실행 중인 프로젝트를 중간에 강제 종료해 배포하지 않습니다.

## 검토 근거

기존 `steps.usage`와 `steps.model`을 집계의 원본으로 사용합니다. `plan-application.ts`의 중복·억제 검사 이후에만 역할 배정 작업을 저장합니다. `PlannedWork`에 남긴 당시 지시가 이후 역할 변경으로 바뀌지 않게 합니다. 사용량을 0으로 채우거나 역할 이름만 표시하는 구현은 완료로 인정하지 않습니다.
