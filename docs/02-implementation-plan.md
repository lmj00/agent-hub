# 진행 상태와 완료 기준

**현재 단계: 핵심 자율 개발 흐름 구현 후, 첫 운영 버전을 준비하는 중입니다.**

“목표를 맡기고 새 지시 없이 다음 작업까지 이어간다”는 흐름을 예제에서 실제 Codex로 확인했습니다. 이를 원격 서버에서 장시간 안정적으로 운영하는 검증은 남아 있습니다.

## 현재 진행 상태

| 영역 | 상태 | 확인한 내용 |
| --- | --- | --- |
| 프로젝트·작업·DB | 구현·검증 | 등록·조회·재시작 보존, 입력·중복·마이그레이션 검사 |
| 로그인·관리 화면 | 구현·검증 | 인증, 목표·작업·실행 이력, 취소·재개, 연결 상태 표시 |
| 실행·복구·제한 | 구현·검증 | 단일 Run, 컨테이너 종료 확인, 제한된 재시도, 한도·기간 예산 대기 |
| 목표 기반 자율 개발 | 구현·검증 | 계획 → 개발 → 실제 테스트 → 독립 검토 → Git 반영 → 다음 작업 |
| 내부 에이전트의 gstack | 구현·검증 | 역할별 고정 지침과 선택·읽기 확인 기록 |
| 목표 전체 완료 | 실제 예제 검증 | 서로 다른 두 작업의 누적 변경, 최종 검산, 완료 후 재시작 |
| Linux·HTTPS 설정 — O1 | 구현·검증 | 실제 Linux 도구의 설정 해석과 격리된 HTTPS 로그인·재시작 검사 |
| 백업·복원 — O2 | 구현·검증 | DB·개발 Git·입력 묶음, 손상 검사, 미리보기, 기존 데이터 보존 |
| 알림·외부 점검 — O3 | 구현·검증 | 전용 상태 조회, 문제 알림·기록·재시도·중복 억제. 실제 수신처 연결은 별도 |
| 운영 안정성 — O4 | 진행 중 | Linux 서비스 재시작 검사 추가. 자원 측정·장시간 관측은 남음 |
| 원격 24시간 운영 | 미검증 | 실제 서버에서 새 지시 없이 작업·대기·복구하는 기록 필요 |

단위별 세부 완료 기록은 [이전 구현 기록](history/implementation-records.md), O1~O4의 구체적인 작업·검증 조건은 [운영 구현 계획](plans/operations.md#implementation-tasks--운영-준비)에 있습니다.

## 다음 커밋 단위

### 장시간 운영과 장애 검증 — O4

프로세스가 살아 있다는 것뿐 아니라, 실제 작업을 이어가고 멈춰야 할 때 기다리는지 확인합니다.

- 실행 중단·재시작 뒤 중복 작업과 미확정 변경이 생기지 않는지 확인합니다.
- 서버·Docker·DB·로그를 포함해 메모리와 디스크 사용량을 측정합니다.
- 시간·AI 호출 상한을 둔 장기 시나리오로 발견 → 개발 → 검증 → 다음 판단을 관측합니다.
- 실제 원격·24시간 기록이 없으면 그 항목을 완료로 표시하지 않습니다.

## 첫 운영 버전의 완료 기준

1. 목표를 등록한 뒤 새 지시 없이 허용 범위 안에서 서로 다른 작업을 발견·개발·검증하고, 다음 작업이 앞선 변경을 사용합니다.
2. 테스트나 검토에서 발견한 결함을 수정하고 다시 확인합니다. 완료 기준을 낮춰 통과시키지 않습니다.
3. 할 일이 없는 대기, 예산·사용 한도 대기, 사용자 조치가 필요한 보류를 구분합니다.
4. 취소·목표 변경·서버 재시작 뒤에도 제한과 변경 이력을 보존하고 중복 실행을 막습니다.
5. 진행 상황과 필요한 조치를 화면·알림·외부 점검으로 확인할 수 있습니다.
6. 백업·복원과 장애 복구를 확인하고, 원격 서버에서 24시간 자율 운영한 기록을 남깁니다.

상세 조건은 [원래 5·6단계의 완료 기준](history/implementation-records.md#5단계-목표-기반-자율-개발과-에이전트-협업)과 [운영 검증 계획](plans/operations.md#test-review)에 보존합니다. 이 요약이 기존 검증 조건을 줄이지 않습니다.

## 검증 결과를 읽을 때

| 근거 | 뜻하는 것 | 아직 뜻하지 않는 것 |
| --- | --- | --- |
| 실제 Codex의 두 작업 누적 실행 | 예제에서 전체 자율 개발 흐름이 연결됨 | 임의 프로젝트의 개선 품질이나 24시간 안정성 보장 |
| 자동 테스트·Linux CI 통과 | 해당 코드와 재현 시나리오의 회귀 검사 | 실제 AWS 설치·공인 인증서·실제 트레이딩 연동 완료 |
| 백업·복원 테스트 | 같은 경로·호환 스키마에서 DB와 Git 상태 복원 | 원본 작업 폴더·인증·이미지까지 포함한 호스트 전체 복구 |

F3 예제는 계획 3건·개발 작업 2건·AI 호출 단계 8건으로 목표를 완료했고, 별도 12개 검산과 재시작 후 중복 없음도 확인했습니다. [상세 근거](history/implementation-records.md#implementation-tasks--5f-완료)를 보존합니다.

현재 서비스 관측은 프로세스·업무 상태를 다룹니다. 실제 트레이딩 서비스 연결과 수익률·위험 지표를 바탕으로 한 전략 개선 품질은 아직 검증하지 않았습니다.

앞선 실제 실행 한 번에서 발생한 macOS SQLite `SIGBUS`의 원인은 아직 확정하지 못했습니다. 이후 성공을 원인 해결의 증거로 보지 않습니다. 부모 Node의 메모리 표본만으로 2GiB 서버에서 전체 시스템을 운영할 수 있다고 결론내리지 않습니다.

## 개발 순서와 기록의 위치

설계 → 작업 API → 실제 AI 연결 → 화면·인증 → 자동 복구 → 자율 개발 → 운영 검증 순서로 진행했습니다. 초기 수동 분석은 연결 확인 단계였으며, 매번 사용자 지시가 필요한 도구로 제품 범위를 축소하지 않습니다.

[과거 단계별 계획·검토·테스트 기록](history/implementation-records.md)은 당시 상황을 보존합니다. 새 작업의 우선순위와 완료 상태는 이 문서를 먼저 확인합니다. 실제 배포와 실제 트레이딩 서비스 변경은 현재 개발 작업의 범위에서 제외하며, 이 때문에 원격 운영의 완료 기준이 사라지는 것은 아닙니다.
